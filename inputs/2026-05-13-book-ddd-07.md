# Chapter 7. Domain Service

## 1. 정의

* 하나의 애그리거트의 책임에 두기에는 애매하거나 큰 도메인(비즈니스) 로직을 담는 객체
* 사용하는 때
  * 여러 애그리거트가 함께 관여하는 로직인 경우
  * 한 애그리거트가 담당하기에는 그 애그리거트의 책임과 맞지 않는 로직인 경우
  * 외부 시스템 연동이 필요한 로직인 경우 ??
* (예) 계좌 간 송금하는 로직
  * 관련 있을 수 있는 애그리거트: 계좌, 돈, 수수료, 환율 등
  * 계좌 간 송금하는 로직이라고 계좌(Account)가 담당하기에는 다양한 애그리거트가 관여할 수 있음



## 2. 특징

* 클래스 명, 메서드 명, 변수 명은 도메인 로직의 의미가 드러나도록 짓는다.

```java
// 클래스명: 송금 서비스
public class TransferService {
	// 메서드 명: 송금  
  public void tranfer(Account fromAcc, Account toAcc, Money amount) {}

}
```

* stateless: 되도록이면 상태를 가지지 않도록 한다.
  * 직접 데이터를 갖기 보다는 외부(다른 애그리거트)로부터 값을 전달 받거나, 다른 애그리거트에게 도메인 서비스를 전달하는 식으로 구현

```java
public class TransferService {
  
  // 메서드 인자로 필요한 정보들을 전달받음
  public void tranfer(Account fromAcc, Account toAcc, Money amount) {}

```

* 애그리거트에서 도메인 서비스를 가져와 쓸 때, 주입해서 쓰지 않는다. (의존성 만들지 않기)
  * 그렇지만 가급적 도메인 서비스 자체를 직접 넘기는 것 보다는, 결과 값만 오가는 것이 깔끔한 것 같음

```java
// 좋지 않은 예시
public class Account {

    private final AccountId id;
    private Money balance;

    // 애그리거트가 도메인 서비스를 필드로 보유
    private final TransferService transferService;
}
```

```java
// 올바른 예시
public class Account {

    private final AccountId id;
    private Money balance;

    public Account(AccountId id, Money balance) {
        this.id = id;
        this.balance = balance;
    }

    // 메서드를 수행하는 시점에 인자로 받는다.
    public void transferTo(
            Account target,
            Money amount,
            TransferService transferService
    ) {
        transferService.validate(this, target, amount);

        this.withdraw(amount);
        target.deposit(amount);
    }
}
```

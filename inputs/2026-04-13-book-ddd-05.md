# 5. 스프링 데이터 JPA를 이용한 조회 기능

## 5-1. CQRS

* 명령(command) 모델과 조회(query) 모델을 분리하는 패턴
* 명령 모델: 상태 변경하는 기능 - (예) 회원 가입, 암호 변경, 주문 취소 등
* 조회 모델: 데이터 보여주는 기능 - (예) 주문 목록, 페이징 등
  * 이후 나올 Specification을 조회 모델에서 복잡한 검색 조건 표현할 때 주로 사용하는 도구 중 하나.



## 5-2. 스펙(Specification)

* 검색 조건을 다양하게 조합해야 할 때 사용
* 애그리거트가 특정 조건을 충족하는지 검사할 때 사용하는 인터페이스
* DDD에서 Specification을 강조하는 이유는 결국 도메인 언어를 코드에 그대로 드러내기 위해서이다.
* 사용하는 이유: 조회 시 다양한 검색 조건이 붙게 되는 경우, 필요한 조합마다 메서드를 정의하는 것은 유지보수 할 메서드의 수를 증가시켜 좋지 않음

```java
// 조건 조합에 따라 메서드가 계속 늘어남 > 대신 메서드 체이닝을 통해 간결하게 해결하고자 한다.
findByStatus(String status);
findByStatusAndMinAmount(String status, long amount);
findByStatusAndMinAmountAndDateRange(...);
findByStatusAndCustomerGrade(...);
```



* Specification 패턴: 비즈니스 규칙(조건)을 하나의 객체로 캡슐화해서 해당 객체가 조건을 만족하는지 판단하거나 검색 조건으로 조합할 수 있게 만드는 패턴
* 엔티티나 밸류 오브젝트 안에 검증/필터 로직을 다 넣으면 모델이 비대해질 수 있다. 이때 Specification으로 분리하면 애그리거트는 상태와 핵심 행위에 집중하고, "어떤 조건을 만족하는가"는 별도 객체가 담당한다.

```java
// 핵심 인터페이스
public interface Specification<T> {
    // 애그리거트가 조건을 만족하는지 체크
    boolean isSatisfiedBy(T target);

    // 다른 애그리거트와 and 조건으로 엮일 때
    default Specification<T> and(Specification<T> other) {
        return t -> this.isSatisfiedBy(t) && other.isSatisfiedBy(t);
    }

    // 다른 애그리거트와 or 조건으로 엮일 때
    default Specification<T> or(Specification<T> other) {
        return t -> this.isSatisfiedBy(t) || other.isSatisfiedBy(t);
    }

  	// 애그리거트가 조건을 충족하지 않는 경우
    default Specification<T> not() {
        return t -> !this.isSatisfiedBy(t);
    }
}
```

```java
// 예시1) 특정 상태를 조건으로 주어 일치하는 주문만 필터링
public class OrderStatusSpec implements Specification<Order> {
    private final String status;

    public OrderStatusSpec(String status) {
        this.status = status;
    }

    @Override
    public boolean isSatisfiedBy(Order order) {
        return order.getStatus().equals(status);
    }
}
```

```java
// 예시 2) "이번 달 확정된 주문 중 10만원 이상"
// - 다른 조건과 조합할 때 and로 쉽게 체이닝
// - 도메인 개념을 코드에 그대로 표현할 수 있다는 점이 장점
Specification<Order> spec = new OrderStatusSpec("CONFIRMED")
    .and(new MinAmountSpec(Money.of(100_000)))
    .and(new OrderDateRangeSpec(
        LocalDate.of(2026, 4, 1),
        LocalDate.of(2026, 4, 30)
    ));
```
